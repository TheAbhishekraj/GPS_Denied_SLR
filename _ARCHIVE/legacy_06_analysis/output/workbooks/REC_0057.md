ROS+Unity: An Eﬃcient High-ﬁdelity 3D
Multi-UAV Navigation and Control Simulator in
GPS-Denied Environments
Wei Meng, Yuchao Hu, Jiaxin Lin, Feng Lin, Rodney Teo
Temasek Laboratories, National University of Singapore
Abstract—In this paper, we will introduce our newly developed
3D simulation system for miniature unmanned aerial vehicles
(UAVs) navigation and control in GPS-denied environments. As
we know, simulation technologies can verify the algorithms and
identify potential problems before the actual ﬂight test and to
make the physical implementation smoothly and successfully. To
enhance the capability of state-of-the-art of research-oriented
UAV simulation system, we develop a 3D simulator based on robot
operation system (ROS) and a game engine, Unity3D. Unity3D has
powerful graphics and can support high-ﬁdelity 3D environments
and sensor modeling which is important when we simulate
sensing technologies in cluttered and harsh environments. On
the other hand, ROS can provide clear software structure and
simultaneous operation between hardware devices for actual
UAVs. By developing data transmitting interface and necessary
sensor modeling techniques, we have successfully glued ROS and
Unity together. The integrated simulator can handle real-time
multi-UAV navigation and control algorithms, including online
processing of a large number of sensor data.
I.
Introduction
Simulation technologies have been widely used by aca-
demic research as a cost-eﬀective way to accelerate processing
procedures. They are especially important in the case of
unmanned aerial vehicles (UAVs) development due to the
complexity involved in outdoor environments and network
communication. UAVs have recently gained great interest
and attention from the academic research groups worldwide
because of their great potential in both military and civil
applications and many groups have constructed their own
UAV platforms [1]–[4]. Nevertheless, generally speaking, the
implementation of UAVs is costly and time consuming. There-
fore, simulation is an eﬀective way to detect and prevent
unnecessary malfunctions of hardware, software and automatic
ﬂight control systems [1].
Simulation technologies can provide great help to verify
the algorithms and identify potential problems before ﬂight
test and to make the physical implementation smoothly and
successfully. Some well-known recent works have demon-
strated the capabilities of 3D simulations. OpenSim [5], Virtual
Robot Experimentation Platform (V-REP) [6], Delta3D [7],
USARSim [8], [9] and Gazebo [10]. OpenSim is one of the
earliest attempts for 3D robotic simulator in 2001. It is a 3D
simulator for autonomous robots that uses OpenGL for real-
time rendering of the robot environment. But the development
is no longer active since October 2008 and also it is not
good at real-time rendering of robot environments. V-REP is
a commercial product and not open-source [8]. Gazebo is a
mature and good open-source simulator but it is developed
and supported mostly on Linux and not meant for hybrid
simulation [8]. To further address the challenges of hybrid
simulation, the Uniﬁed System for Automation and Robotics
Simulator (USARSim), a high-ﬁdelity simulation tool based
on Unreal technology gained more researchers’ attention, as it
represents robot automation and behavior, as well as renders
user interface elements precisely [11]. HNMSim, a hybrid
3D simulator based on USARSim, was used in our lab for
UAV testing simulations. Its general structure is hardware-
in-the-loop software and uses methodology, namely, Socket
connection, model creation and control design [8]. To add on
the current HNMSim, several high-ﬁdelity 3D maps of forest
and city could be built to test various algorithms.
As there are many 3D simulator available as stated above,
why we still need to develop our new UAV simulation system?
The main reason is that most of the simulation system available
cannot fulﬁl our project requirements. In our UAV project, the
UAVs are expected to cooperatively and autonomously operate
in GPS-denied foliage or urban environments. Light Detection
and Ranging (LIDAR) based simultaneous localization and
mapping (SLAM) algorithm needs to be simulated in real-time.
According to our knowledge, most of the simulation systems
are not ’real’ enough. Firstly, the environments, especially, the
collision level of the trees and buildings needs to be modeled
as real as possible. Secondly, UAV sensors are required to be
modeled as real and need to run in high frequency level.
In this paper, a novel hybrid 3D simulation is developed
based on Robot Operation System (ROS) and a game engine:
Unity 3D. ROS [12] is an open source framework designed
to provide an abstraction layer to complex robotic hardware
and software conﬁguration. It provides libraries and tools to
help software developers create robot applications and has
found wide use in both industry and academia. Gazebo which
was mentioned above also origins from ROS. Unity3D is
a ﬂexible and powerful development platform for creating
multiplatform 3D and 2D games and interactive experiences.
This game engine which supports almost every platforms is
chosen to be the simulation server of this project. Besides game
developments, Unity3D could also be employed by academic
research [13]. It has been developed as simulator in geographic
information system [14], the communication system for Moon
base simulated scenario [15], and wind energy development
[15]. These implications proves that Unity3D can also be
used in academic area with vivid and highly interactive per-
formance. The main reason of choosing Unity 3D as the
visualization tool is that it is easier for entry-level researchers
to develop their UAV applications, especially, to build the

II.
Background
As introduced in the last section, the main objective of
this work is to develop a hybrid 3D simulation system for
UAV navigation and control in GPS-denied foliage or urban
environments. Oﬀcourse, the developed simulator can also be
extended for other usages. Before presenting our developed
simulation system, our UAV project background is brieﬂy
introduced.
In this project, we propose to develop an advanced outdoor
navigation system to explore the theories and technologies that
enable UAVs to realize autonomous navigation in forest or
urban cluttered environments. To realize the navigation system,
several main topics need to be investigated, including advanced
sensing technologies, sophisticated navigation approaches, as
well as SLAM techniques. A variety of sensing technologies
are considered in the project, including electro-optical sensors
(EO), LIDAR, inertial measurement units (IMU), the GPS,
and so on. The fusion techniques are investigated to combine
measurements of these sensing technologies to realize obstacle
detection and robust navigation even at the loss of GPS signal.
In addition, based on obstacle detection, dynamic 3D path
planning scheme is studied to determinate a safe path for the
UAV to operate in foliage environments.
For the UAV mission, multiple UAVs are supposed to
cooperatively search a large-scale forest environment. UAVs
need to continuously communicate with others and share the
map information to guarantee the full coverage of the mission
space.
In order to verify the developed UAV navigation and path
planning algorithms, a useful 3D simulation system needs to
be developed. As the worth of simulated results is directly
decided by the ﬁdelity of the simulated environment side,
one crucial challenge in UAV simulation technologies is to
implement a high-ﬁdelity hybrid networked multi-agent system
simulator. Hence, Unity3D, the game engine which boasts
powerful virtual scene editing function, rendering function and
powerful logic management function is chosen to build the
platform of this high-ﬁdelity simulator. Besides, ROS, the open
source operating system for robot, is chosen as the platform
for the simulator. In the next section, the main structure of the
developed 3D multi-UAV simulator will be presented.
III.
Main Structure
Before going to illustrate the structure of our developed
simulation system, two frameworks, namely Unity3D and ROS
are brieﬂy introduced.
A. Unity3D
Unity3D is a game development ecosystem: a powerful
rendering engine fully integrated with a complete set of
intuitive tools and rapid workﬂows to create interactive 3D
and 2D content; easy multiplatform publishing; thousands of
quality, ready-made assets in the Asset Store and a knowledge-
sharing community [16]. Unity3D allows game developers to
create games that delight players on any platform. The high
ﬁdelity model, live environment and capability to be adapted
to any platform which can be achieved by Unity3D make it
the best choice of our 3D high-ﬁdelity simulator.
Moreover, natural environment and weather conditions can
be simulated in Unity3D, too, to monitor the possible complex
outdoor inﬂuence on UAV in physical test through simulations.
Though, it may still be far away from the actual light, but we
can continue employ the potential of Unity3D in environment
simulation.
Another crucial advantage of Unity3D compared to our
existing simulator is that the collision regions of objects can be
as narrow and detailed as the shape of the objects themselves.
B. Robot Operating System
Fig. 1.
Hierarchical structure of ROS
ROS is an open source operating system for robots, which
is originally developed in 2007 at the Stanford Artiﬁcial
Intelligence Laboratory [12]. As an open source platform,
ROS has tremendous libraries and visualizers especially for
robots which are developed by the diverse worldwide research
communities. The modular architecture and easily syncing
threads make ROS ﬂexible and convenient. Same nodes can
be multiply used for diﬀerent operations. Figure 1 shows the
hierarchical modular structure of ROS.
ROS consists of a large range of tools and services that
both users and developers can beneﬁt from. Debugging at all
levels of the software is made possible with the full source
code of ROS being publicly available.
Currently, many UAV community users and developers use
ROS to develop and test their algorithms. It is quite convenient
since after testing algorithms in ROS, they can be directly
implemented in the UAV processor with minor changes.

IV.
Technical Issue and Our Approach
A. Interface Between ROS and Unity3D
The exchange of data packets between the Unity3D server
and the ROS client is achieved by TCP/IP protocol. An
interface between ROS and Unity3D has been developed which
can support multiple UAVs applications.
The ROS node, unitysocket will communicate to the preset
IP address which should be the address of the Unity3D server.
For every spin, the ROS client receives laser scan data (1081
data array for 270 degrees, the same as real 30m URG laser
scanner) and publishes it as LaserScan message onto the
topic laser/horizontal/scan. It also publishes the transformation
required by ROS based on the state of Unity3D UAV model.
This node computes the transformation of vertical laser scanner
based on the x, y and z rotation of Unity3D laser model. With
the help of TCP/IP communication, wireless communication
between diﬀerent Unity3D servers and clients is possible.
Originally a local interface which allows Unity3D and c++
control logic to assess same memory for data exchange was
implemented. However, we realized the entire system will
crashed after around 10,000 runs due to the limited space
of memory. Using TCP/IP instead, not only solve this issue,
but also achieve high speed communication between remote
server and client. Currently, we have managed to develop an
ROS/Unity3D interface, which can support multi-UAVs data
transmissions.
B. 3D Environment Modeling
In order to improve the conﬁdence level of simulation
system, 3D virtual environments need to be modeled as real
as possible. According to our experience, urban environment
is easier to be modeled than forest one. Since trees are the key
components in the forest map, we give a brief introduction its
modeling technique.
Actually, there are many methods can be used to model the
trees, depending how much details required. From Figure 3,
trees in Unity3D, it can be easily observed that the collision
regions of these trees are much more similar to actual trees
compared to simple cylindrical space in other simulations.
With such detailed collision region, the simulated results of
the performance of obstacle avoidance is more precise and
provide higher credibility in verifying the related algorithms.

C. UAV Sensor Modeling
Fig. 6.
LIDAR sensor in operating
1) LIDAR: The LIDAR sensor used in our UAV system
is Hokuyo UTM-30LX. The main features modeled in the
simulator are: (1) Detectable range is .1m-30m (2) Scan-
ning angle 270 deg (3) Scan speed 25ms (4) Compact Size:
W60xD60xH87mm (5) Small weight, 370g.
There are two LIDAR sensors mounted on our UAV plat-
form. One of them is placed static on the top of the platform.
The main purpose of this LIDAR sensor is used by SLAM
to estimate the location of UAVs. Another LIDAR sensor is
mounted on the front part of the UAV platform. Specially, this
LIDAR sensor is keep tilting (nodding up and down) according
to a certain speed to obtain 3D obstacle information. These
two LIDAR sensors’ sensing data is quite important, since
these data will be used for localization and mapping, and also
for 3D path planning. As seen from Figure 6, two LIDAR
sensors of one UAV are operating simultaneously in the forest
environment, where red color representing nodding LIDAR
and blue color representing horizontal static LIDAR.
According to LIDAR sensor’s speciﬁcation, there are total
1081 data for each 270 degree scan. The scanning frequency is
around 40 Hz. In Unity3D, one straightforward technique is to
use Physics.Raycast scripting API to develop our customized
LIDAR sensor model. In our Raycast script, scanning range
and angle should be deﬁned in details. Both LIDAR sensors
developed can be run simultaneously.
For single UAV case, based on above development, the
simulator can run smoothly. The FPS can approach 40, which
means the simulation system can run in real-time. However,
if there are several UAVs run simultaneously in the same
workstation, we ﬁnd that FPS will drop dramatically. The main
problem origins from 3D game engines. Usually, for Raycast
in Unity3D, it run in the main thread of CPU. When we run
several UAVs in the same workstation, Raycast calculation will
take most of the CPU resource.
To let multiple UAVs run LIDAR sensors simultaneously,
we turn to GPU for Raycast calculation. The main idea is that
ﬁrstly, the environment mesh information should be transmit to
GPU. Then GPU will run the customized Raycast calculations.
Since GPU has lots of caches available, the calculation can run
eﬃciently.
2) Camera: The camera sensor development is easy in the
most of the game engine. In our system, one camera is mounted
static on the front of the UAV platform. The main purpose of
the camera is for target detection.

VI.
Conclusion
In this paper, we gave a brief introduction to our newly
developed ROS/Unity3D hybrid UAV simulation system. By
developing the sensor modeling, especially LIDAR sensor,
interface between ROS and Unity3D, we have managed to
make the simulation system run smoothly. Since the simulation
structure is almost the same with real system, the developed
simulator is useful for testing all on-line algorithms. For the
future work, we will develop hardware-in-the-loop simulation
system.
