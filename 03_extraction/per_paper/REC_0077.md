## 3. Abstract / TL;DR
This paper presents a 3D path planning and navigation framework for UAVs in static, GPS-denied environments. The system uses stereovision and visual-inertial odometry (VIO) for SLAM to build an OctoMap (3D occupancy grid). The core contribution is an advanced sampling-based path planner operating in an SE(3) state space that models the drone as a rigid body and computes paths optimizing a weighted cost function (combining length, clearance, and orientation smoothness), followed by B-spline smoothing. The paper evaluates this with an NVIDIA Jetson AGX Orin–equipped multicopter using MAVROS and PX4.

## 5. Navigation/Localisation Method
- **Approach:** Visual-Inertial SLAM & sampling-based path planning.
- **Methodology:** A stereovision camera and IMU feed into VIO for SLAM, outputting an OctoMap. OMPL generates paths using RRT-Connect (or other variants) over a bounded SE(3) space, meaning the UAV is modeled as a 3D rigid body (via Flexible Collision Library, FCL) rather than a point mass. Paths optimize for length, clearance, and rotation smoothness. Final paths are shortcuts and smoothed via B-splines, then followed via MAVROS OFFBOARD position setpoints [p.1-2, p.4-5].
- **Type:** Localisation + Mapping + Path Planning

## 9. Ablation / Sensitivity
Benchmarked 6 OMPL planners (RRT, RRT*, RRTConnect, LBTRRT, InformedRRT*, RRTstatic). Found LBTRRT used most memory (~190 MB vs 165 MB); InformedRRT* and RRTstatic had fastest simplification times (<0.5 s), while RRT* and RRT were slowest (>1.0 s). Simplification took ~13% of total runtime. [p.6-7]

## 10. Stated Limitations
- Static environments only: "path planning in static environments" [p.1]
- Altitude overshoot: "The maximum Z error reaches a value of 3.105 meters... associated with altitude settling after takeoff" [p.7]
- Computation cost: Continuous collision detection is too computationally expensive, necessitating discrete intermediate states validation [p.4]
